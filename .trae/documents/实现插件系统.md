# 插件系统实现方案

## 1. 设计思路

* 利用现有项目架构，在关键流程节点插入插件处理逻辑

* 采用事件驱动模式，让插件可以注册并监听特定事件

* 设计灵活的插件接口，支持不同类型的插件功能

* 尽量减少对原有代码的修改，通过局部扩展实现

## 2. 关键实现点

### 2.1 插件系统核心架构

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  原有流程节点   │────▶│  插件管理器     │────▶│  插件实例       │
│  (startToChat)  │     │  (PluginManager)│     │                 │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                                ▲                       │
                                │                       ▼
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  TTS模块        │◀────│  处理结果返回   │◀────│  文本预处理     │
│                 │     │                 │     │                 │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

### 2.2 插件接口设计

```python
class BasePlugin:
    def __init__(self):
        self.name = "BasePlugin"
        self.description = "基础插件类"
    
    async def pre_process_text(self, conn, text):
        """文本预处理方法
        Args:
            conn: 连接对象
            text: 待处理的文本
        Returns:
            tuple: (处理结果, 是否拦截)
                - 处理结果: 处理后的文本
                - 是否拦截: True表示拦截，不再进入LLM流程；False表示继续原有流程
        """
        return text, False
```

### 2.3 插件管理器设计

```python
class PluginManager:
    def __init__(self):
        self.plugins = []
    
    def register_plugin(self, plugin):
        """注册插件"""
        self.plugins.append(plugin)
    
    async def process_text(self, conn, text):
        """处理文本，依次调用所有插件
        Returns:
            tuple: (处理结果, 是否拦截)
        """
        for plugin in self.plugins:
            try:
                text, intercepted = await plugin.pre_process_text(conn, text)
                if intercepted:
                    return text, True
            except Exception as e:
                conn.logger.error(f"插件 {plugin.name} 处理失败: {e}")
        return text, False
```

## 3. 实现步骤

### 3.1 创建插件系统核心文件

1. 创建 `core/plugin/plugin_base.py` - 插件基类定义
2. 创建 `core/plugin/plugin_manager.py` - 插件管理器
3. 创建 `core/plugin/__init__.py` - 插件系统初始化

### 3.2 修改现有代码，插入插件调用

1. 修改 `core/handle/receiveAudioHandle.py`，在 `startToChat` 函数中添加插件处理逻辑
2. 在 `core/connection.py` 中初始化插件管理器
3. 在 `app.py` 中加载插件

### 3.3 创建测试插件

1. 在 `plugins_func` 目录下创建测试插件文件
2. 实现文本预处理逻辑，符合规则的文本直接拦截
3. 注册插件到插件管理器

### 3.4 测试验证

1. 启动服务，测试插件功能
2. 验证符合规则的文本是否被正确拦截
3. 验证不符合规则的文本是否正常进入原有流程

## 5. 预期效果

* 插件系统能够正常加载和管理插件

* 测试插件能够在TTS模块后、LLM模块前处理文本

* 符合规则的文本被正确拦截，直接输出到TTS

* 不符合规则的文本继续原有流程，进入LLM处理

* 系统运行稳定，没有明显性能影响

## 6. 架构影响评估

* 对原有架构影响较小，仅在关键节点插入插件调用

* 插件系统采用松耦合设计，便于扩展和维护

* 不影响原有功能的正常运行

* 为后续功能扩展提供了灵活的插件机制
