# 天气插件使用指南

## 概述

天气插件 `get_weather` 是小智ESP32语音助手的核心功能之一，支持通过语音查询全国各地的天气信息。插件基于和风天气API，提供实时天气和7天天气预报功能。

## API Key 申请指南

### 1. 注册和风天气账号

1. 访问 [和风天气控制台](https://console.qweather.com/)
2. 注册账号并完成邮箱验证
3. 登录控制台

### 2. 创建应用获取API Key

1. 进入控制台后，点击右侧["项目管理"](https://console.qweather.com/project?lang=zh) → "创建项目"
2. 填写项目信息：
   - **项目名称**：如"小智语音助手"
3. 点击保存
4. 项目创建完成后，在该项目中点击"创建凭据"
5. 填写凭据信息：
    - **凭据名称**：如"小智语音助手"
    - **身份认证方式**：选择"API Key"
6. 点击保存
7. 在凭据中复制`API Key`，这是第一个关键的配置信息

### 3. 获取API Host

1. 在控制台中点击["设置"](https://console.qweather.com/setting?lang=zh) → "API Host"
2. 查看分配给你的专属`API Host`地址，这个是第二个关键的配置信息

以上操作，会得到两个重要的配置信息:`API Key`和`API Host`

## 配置方式(任选一种)

### 方式1. 如果你使用了智控台部署（推荐）

1. 登录智控台
2. 进入"角色配置"页面
3. 选择要配置的智能体
4. 点击"编辑功能"按钮
5. 在右侧参数配置区域找到"天气查询"插件
6. 勾选"天气查询"
7. 将复制过来的第一个关键配置`API Key`,填入到`天气插件 API 密钥`里
8. 将复制过来的第二个关键配置`API Host`,填入到`开发者 API Host`里
9. 保存配置，再保存智能体配置

智控台这边插件参数里的「API 密钥」和「API Host」两栏默认是空的：仓库早期版本内置过一把已经失效的和风天气凭据，数据库变更脚本把它清掉了，得照着本文件的「API Key 申请指南」申请自己的一套再填。字段名后面括号里写了申请路径。

脚本只清仓库内置的那一把，你自己填的凭据原样保留。以后要换凭据，在智控台「角色配置 → 编辑功能 → 天气查询」的参数表单里改完保存就行。清理的范围见文末那节。

### 方式2. 如果你只是单模块xiaozhi-server部署

在 `data/.config.yaml` 中配置：

1. 将复制过来的第一个关键配置`API Key`,填入到`api_key`里
2. 将复制过来的第二个关键配置`API Host`,填入到`api_host`里
3. 将你所在的城市填入到`default_location`里，例如`广州`

```yaml
plugins:
  get_weather:
    api_key: "你的和风天气API密钥"
    api_host: "你的和风天气API主机地址"
    default_location: "你的默认查询城市"
```

## 智控台那边内置的凭据清到了什么程度

早期版本把一把和风天气的 API Key 和一个 API Host 写在模型提供方「天气插件」那一行的字段默认值里，角色配置的表单拿这个默认值预填，不填就等于沿用仓库里那一份。那把 key 已经失效，仓库也不该带着凭据分发。数据库变更脚本做两件事：

- 把那一行的默认值清空，同时把申请路径写进字段名，用户在界面上能直接看到去哪儿申请
- 把已有智能体的参数里还等于那把内置 key 的项清空

清不掉的有两类。一是管理员自己填的值，脚本不动，误清就是误删人家的凭据。二是这一种：管理员在界面上改过那一行的默认值之后，仓库内置的那把失效 key 就被覆盖了，再也认不出来，早于管理员改动建立、参数里还存着那把旧内置 key 的智能体不会被自动清掉，只能由管理员自己在界面上改。

这两条清理跟着另外两个改动走：#3474 让插件在没有凭据时给出提示而不是报错，#3475 让 CI 真的会跑测试，这条变更脚本才在 CI 里被验证过。两者都要先落地。
